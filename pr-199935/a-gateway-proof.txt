# PR #199935 — shipped-entry-point proof (Gateway, no device identity)

Purpose: prove that the image inline-preview cap fix (256 KiB -> 5 MiB, incl. the
P2 remote-bypass fix in toSessionFileEntry) works through the SHIPPED gateway
entry point, not just unit tests.

Run: 2026-11-17T01:06 (+08:00), local dev host (no production systems involved).

Setup
- Entry point: `node dist/index.js gateway --port 18791`
  (dist/index.js is the shipped CLI/gateway entry of the built distribution).
  The tree is a release tarball (non-git), so verifyBuiltGatewayHead stamps
  head=null; this is a documented pre-stamp launch.
- Isolated env: HOME=/tmp/oc-proof/home, OPENCLAW_STATE_DIR=$HOME/.openclaw.
- Config ($HOME/.openclaw/openclaw.json, written before launch):
  {"gateway":{"mode":"local","auth":{"mode":"none"},"bind":"loopback"}}
  (gateway.mode is required by the startup validation gate; auth.mode=none +
  loopback bind + role=operator + no device identity = no-device connect.)
- Session workspace root: the gateway materialized the main agent's workspace
  at $STATE_DIR/workspace (legacy data-owner default) on first use.
  Test fixtures were placed there after launch (data files only; config and
  state DB were never mutated while the gateway ran):
    big-png.png    1,703,501 B  (> 256 KiB cap on main, <= 5 MiB cap)
    too-big-png.png 5,242,881 B  (> 5 MiB cap)
- Fixture generator: same buildPng() as
  src/gateway/server-methods/workspace-files.preview-cap.test.ts.
- Client: packages/gateway-client/dist/index.mjs (built), mode=backend,
  role=operator, scopes=[operator.admin], deviceIdentity=null,
  url=ws://127.0.0.1:18791.
- Note: requestTimeoutMs=180000 (default 30000) because a concurrent local
  docs/DTS build caused event-loop stalls up to ~7.5s during this window;
  server-side request processing was unaffected.

Expected result on unpatched main: big-png.png -> previewKind "unsupported",
no content (256 KiB cap). After the fix: previewKind "image", full base64
content. too-big-png.png stays "unsupported" with no content (> 5 MiB cap,
local sniff-verified path; remote "unsupported" workspaces keep the generic
256 KiB cap per the main/#159895 contract — see PR body).
